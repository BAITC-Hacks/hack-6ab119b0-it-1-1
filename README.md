# 1. Beeline Adaptive Campaign Agent

## 2. Description

Offline tariff campaign planning for HackAlem AI Track 04. The agent learns from paid, noisy pilots and returns a resource-constrained campaign plan.

## 3. Implemented features

- Public `Agent.act(env)` entry point, entirely contained in `agent.py`.
- Historical ranking, adaptive pilot confirmation, direct channel comparisons, and uncertainty-aware selection.
- Full-audience budget/contact accounting and a minimum-exposure fallback.
- Reproducible `submission.csv`, generated by the organizer script with seed 42.

## 4. Approach

Partition customers by current tariff and ARPU segment, splitting oversized groups with supported usage filters. Historical median ARPU changes rank initial hypotheses but do not determine final effects.

Screen valuable audiences, test alternative channels directly, and allocate further pilots according to uncertainty and audience value. Estimate each candidate's effect from sample-size-weighted pilot observations; use the documented noise standard deviation to calculate standard error. Select disjoint audiences whose estimated gain remains positive after a one-standard-error discount and communication costs. If none qualify, choose the smallest feasible observed audience. This fallback can lose money.

The agent uses only the public environment interface and participant historical data. It does not inspect hidden effects or evaluator internals.

## 5. Technologies

Python, pandas, and NumPy. Validated in Docker with Python 3.13.15, pandas 2.3.3, and NumPy 2.5.3. Dependencies are declared in `requirements.txt`.

## 6. Architecture and files

`agent.py` contains the complete policy and its entry point. `submission.csv` contains the generated final campaigns. `requirements.txt` declares dependencies. This README describes execution and limitations. No helper package or web application is required.

## 7. Installation and launch

Extract the organizer participant pack, then copy these four submission files into its root. Keep its `data/` directory, `customer_profile.csv`, dictionaries, environment, evaluator, and generator unchanged. These organizer assets are required inputs and are not duplicated in this repository.

From that assembled directory, create a local Python 3.13 virtual environment:

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

## 8. Testing and results

The unchanged official evaluator returns PASS on seed 42: net gain **336,611.23** conventional units, **49,936 / 100,000** budget spent, **9,334 / 15,000** contacts, **20 pilots**, and **2 final campaigns**.

Across seeds 0-9, this policy has mean net gain **309,345**, median **403,836**, and **7/10** profitable runs. The supplied starter has mean **-480,836** and **0/10** profitable runs. This policy beats the starter on all ten paired seeds, but its worst run is **-372,515**.

## 9. Data and integrations

All customer and history inputs come from the organizer's synthetic participant pack. Monetary values use conventional units, not tenge. The submitted agent needs no API key or network access after dependency installation. Codex assisted development and testing. The separate OpenAI post-run analyst from the development application is outside this minimal submission package.

## 10. Limitations

Mock effects differ from hidden judging effects. Three of ten tested seeds lose money; this is a working policy with remaining robustness limitations, not a guarantee of profit or ranking. The uncertainty discount is a heuristic rather than a calibrated statistical guarantee. Historical data comes from a different population, and final-plan estimates do not reproduce the evaluator's pilot/final overlap accounting.

## 11. Deployment

No deployment is required for this offline submission. Use the organizer harness and virtual environment commands above.
