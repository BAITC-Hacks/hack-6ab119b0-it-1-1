# Агент управления тарифными маркетинговыми кампаниями

Команда **It 1+1** · HackAlem AI · трек 04 «Телекоммуникации» · владелец кейса — Билайн

## Краткое описание

Маркетинговая кампания по смене тарифа легко уходит в минус: значительная часть переходов
заканчивается downsell — абонент после смены платит меньше, — а сам контакт не бесплатен.
Сегодня аналитик выбирает сегменты и делит бюджет вручную и не успевает перебрать варианты.

Решение — агент, который сам исследует базу пилотными кампаниями и возвращает план не более
чем из 10 кампаний: кого, на какой тариф и через какой канал. Пользователь — **аналитик
маркетинга, планирующий кампании на следующий месяц**.

## Что реализовано

- Построение априорной оценки эффекта по истории смен тарифов для связок
  «текущий тариф × ARPU-сегмент × целевой тариф».
- Разведка пилотными кампаниями через бесплатный канал `push`: до 20 пилотов по 200 абонентов,
  разведка не тратит денежный бюджет.
- Байесовское сжатие результата пилота к априору с учётом погрешности наблюдения
  (шум пилота = 0.804/√n).
- Распределение двух независимых ограничений — бюджета 100 000 у.е. и охвата 15 000 контактов:
  базовое покрытие бесплатным каналом и жадный «апгрейд» канала там, где прибавка к эффекту
  на один рубль максимальна.
- Сборка до 10 кампаний с объединением сегментов и сортировкой по ценности контакта.
- Страховочная ветка: при исключении в основной логике агент возвращает безопасный минимум,
  а не падает.

Измерено на мок-среде командой `python local_eval.py --runs 10`:

|---|---|---|
| Статус (seed 42) | FAIL | **PASS** |
| Чистый результат, медиана 10 прогонов | −357 948 | **+4 378 618** |
| Худший прогон | −1 019 431 | **+4 193 394** |
| Лучший прогон | −76 493 | +4 701 460 |
| Прогонов в плюс | 0 из 10 | **10 из 10** |
| Абонентов с отрицательным эффектом (seed 42) | 66,3 % | **0 %** |

На seed 42: чистый результат **4 270 729** (+2,835 % к baseline 150 641 084), охвачено
9 746 уникальных абонентов (41,6 % базы), израсходован весь лимит охвата и 34,9 % бюджета.

## Как работает решение

1. Агент получает от среды профиль аудитории (23 441 абонент), справочники тарифов и каналов
   и остатки лимитов.
2. По истории смен тарифов строится априорная оценка эффекта; кандидаты ранжируются по
   произведению «эффект × средний ARPU сегмента × размер сегмента».
3. Агент проводит пилоты бесплатным каналом: по одной лучшей гипотезе на 16 самых ценных
   сегментов, оставшиеся пилоты — на вторую гипотезу для крупнейших сегментов.
4. Результат каждого пилота смешивается с априором: вес наблюдения считается из его дисперсии,
   поэтому шумная оценка на малой выборке не может одна определить решение.
5. Сегменты с положительной оценкой получают канал: базово бесплатный `push`, а бюджет
   расходуется жадно — по убыванию прибавки эффекта на рубль. Канал у сегмента ровно один,
   иначе одни и те же абоненты расходуют лимит охвата дважды.
6. На выходе — до 10 кампаний, платные первыми: скоринг расходует бюджет и охват по порядку.

## Технологии

- Python 3.11+, `pandas`, `numpy` — весь расчёт.
- Среда, скоринг и утилиты проверки — файлы из пакета участника, включены без изменений:
  `environment.py`, `scoring_core.py`, `mock_environment.py`, `local_eval.py`,
  `make_submission.py`, `agent_template.py`.
- **LLM в контуре принятия решений намеренно не используется.** Организаторы перезапускают
  агента на мок-среде с тем же seed и сверяют результат с `submission.csv`, поэтому решение
  обязано быть детерминированным. Своей случайности у агента нет: вся случайность живёт в среде
  и управляется её seed. Переменная `OPENAI_API_KEY` описана в `.env.example` на случай
  необязательного текстового отчёта и на стратегию не влияет.

## Архитектура проекта

Один модуль `agent.py` с классом `Agent` — интерфейс задан организаторами. Внутри четыре
изолированных шага, каждый тестируется отдельно:

```
build_prior()        история смен тарифов -> априорная оценка эффекта по связкам
Agent._candidates()  профиль аудитории + априор -> очередь гипотез для пилотов
Agent._explore()     пилоты через push -> сжатые оценки с их погрешностью
Agent._allocate()    оценки + лимиты -> выбор канала для каждого сегмента
Agent._assemble()    сегменты -> до 10 кампаний, платные первыми
Agent._fallback()    страховка: безопасный минимум при исключении
```

Параметры стратегии вынесены в константы наверху файла (`PRIOR_SD`, `PILOT_SIZE`, `MIN_CELL`,
`Z_SAFETY`, `TARGETS_PER_CELL`, `FIRST_PASS_CELLS`) — их можно менять, не трогая логику.

## Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  source .venv/bin/activate — Linux/macOS
pip install -r requirements.txt
```

Данные кейса в репозиторий не коммитятся (см. «Данные и интеграции»). Перед запуском положите
в корень проекта из пакета участника: `customer_profile.csv` и папку `data/`
(`change_tariff.csv`, `dict_tariff.csv`, `traffic.csv`, `arpu_monthly.csv`).

```bash
python local_eval.py            # один прогон с отчётом
python local_eval.py --runs 10  # 10 прогонов с разными seed: проверка устойчивости
python make_submission.py       # генерация submission.csv
```

## Как проверить решение

1. `python local_eval.py` — статус должен быть **PASS**, чистый результат положительный,
   `Risk score` равен нулю, число пилотов больше нуля.
2. `python local_eval.py --runs 10` — все 10 прогонов в плюсе, знак между сидами не меняется.
   Это прямая проверка устойчивости к неудачной серии пилотов.
3. `python make_submission.py` — создаёт `submission.csv` из 9 кампаний; повторный запуск даёт
   побайтово тот же файл, то есть решение воспроизводимо.
4. Сравнение с эталоном: замените в `local_eval.py` импорт на `from agent_template import Agent`
   и убедитесь, что шаблон уходит в минус на тех же сидах.

## Данные и интеграции

Все данные синтезированы организаторами специально для хакатона — это не выгрузка из систем
оператора. Используются:

| Файл | Что берём |
|---|---|
| `customer_profile.csv` | аудитория 23 441 абонент: текущий тариф, ARPU-сегмент, `predicted_arpu` |
| `data/change_tariff.csv` | 14 823 исторические смены тарифа — источник априорной оценки |
| `data/dict_tariff.csv` | справочник 21 тарифа |

`traffic.csv` и `arpu_monthly.csv` в текущей версии не используются: сегменты в профиле уже
посчитаны по ним организаторами.

Данные и `.env` исключены из репозитория через `.gitignore`: инструкция по кибербезопасности
запрещает распространять данные хакатона и размещать секреты в репозитории. Внешние API
решение не вызывает.

## Ограничения

- Эффекты на судействе отличаются от мок-среды, поэтому абсолютные числа выше — показатель
  поведения агента, а не будущего балла. Под конкретные числа мока подгонки нет: настраивались
  ширина разведки и сила сжатия, а не эффекты связок.
- Априор строится по истории, описывающей другую выборку абонентов. Если на судействе
  ранжирование связок окажется принципиально иным, часть пилотов уйдёт впустую.
- Эффект оценивается на уровне сегмента «текущий тариф × ARPU-сегмент», без модели на уровне
  отдельного абонента. Сегменты `data_segment` и `call_segment` в выборе цели не участвуют.
- Бюджет расходуется не полностью (34,9 % на seed 42): все выгодные апгрейды канала уже
  применены, остальные не окупают стоимость контакта. Упирается решение в лимит охвата.
- Повторных пилотов для уточнения спорных оценок нет: лимит в 20 пилотов расходуется за один
  проход.
- `Z_SAFETY = 0` — агент берёт сегмент при положительной сжатой оценке без дополнительной маржи.
  Это решение подтверждено замером на 20 прогонах, но при эффектах, близких к нулю, параметр
  стоит поднять.
