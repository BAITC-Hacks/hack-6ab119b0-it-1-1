## 1. Что за задача

Трек 04 «Телекоммуникации», владелец кейса — Билайн. Нужен агент, который выбирает
маркетинговые кампании по смене тарифа и возвращает план не более чем из 10 кампаний.
Одна кампания = три решения: кого (фильтр по сегменту), на какой тариф, через какой канал.

Сдаются **`agent.py` и `submission.csv`**. Интерфейс задан организаторами:

```python
class Agent:
    def act(self, env) -> list[dict]: ...
```

Все данные кейса синтетические, сгенерированы организаторами специально для хакатона.

### Жёсткие ограничения (действуют одновременно)

| Ограничение | Значение |
|---|---|
| Кампаний в плане | не более 10 |
| Абонентов на кампанию | не более 5 000 |
| Контактов всего (включая пилотные) | 15 000 |
| Бюджет на все контакты (включая пилотные) | 100 000 у.е. |
| Пилотов | не более 20, по 10–200 абонентов |
| Время работы агента | 5–10 минут (в гайде 10, в шаблоне 5 — ориентируемся на 5) |

Каналы: `push` 0 у.е. ×0.50 · `sms` 4 ×0.65 · `digital_ads` 22 ×0.85 · `call` 160 ×1.20.

**Запрещено:** доставать модель эффектов в обход пилотов (`__closure__`, `gc`, чтение файлов
организатора) — результат аннулируется, код проверяется автоматически. Хардкодить ключ LLM
нельзя, только `os.environ["OPENAI_API_KEY"]`.

## 2. Как устроена среда — это важнее всего остального

Читать `environment.py` и `scoring_core.py`. Ключевые факты, добытые оттуда:

**Формула эффекта.** Для абонента:

```
lift = arpu_change_pct(откуда, ARPU-сегмент, куда)
       * clip(conversion_rate * множитель_канала, 1.0)
       * predicted_arpu(абонента)
```

Из этого следуют три вывода, на которых стоит всё решение:

1. **Эффект зависит только от тройки (текущий тариф, `arpu_segment`, целевой тариф).**
   `data_segment` и `call_segment` в формулу не входят — фильтры по ним лишь сужают аудиторию
   и меняют состав по `predicted_arpu`.
2. **Канал входит только множителем.** Поэтому бесплатный `push` меряет ту же величину, что и
   `call`, просто в другом масштабе. Разведка через push не стоит денег вообще.
   Оговорка: при `conversion_rate * множитель > 1` срабатывает клиппинг, и линейный пересчёт
   между каналами перестаёт быть точным.
3. **Эффект пропорционален `predicted_arpu`**, то есть один и тот же процент на дорогом
   абоненте стоит кратно больше.

**Шум пилота.** `PER_CUSTOMER_STD = 0.804`, пилот возвращает среднее по выборке, поэтому
шум = `0.804/sqrt(n)`. При n=200 это 0.057 при типичных эффектах 0.2–0.45 — убыточная связка
легко выглядит прибыльной. Это главная ловушка кейса.

**Скоринг (`score_campaigns`).** Кампании обрабатываются **по порядку**, расходуя охват и
бюджет; кампания, не влезшая в остаток, обрезается. Затем каждый абонент дедуплицируется —
засчитывается **один раз по лучшей для него кампании**. Итог:
`net = сумма лучших lift по уникальным абонентам − стоимость всех контактов`. Статус PASS при
`net > 0`. Baseline «ничего не делать» = 150 641 084.

**Пилоты идут в зачёт.** Пилотные кампании попадают в скоринг наравне с финальными, с
фиксированной выборкой (`explicit_ids`). То есть неудачный пилот — это не «репетиция», а
реальный убыток.

**Воспроизводимость.** `make_submission.py` прогоняет агента на моке с `seed=42` и пишет
`submission.csv`. Организаторы повторят этот прогон и сверят файл. **Поэтому агент обязан быть
детерминированным.** Своей случайности у него быть не должно — вся случайность в среде.
Это и есть причина, по которой LLM в контур принятия решений не заведён.

**Мок ≠ судейство.** `mock_environment.py` строит модель эффектов простым усреднением из
`data/change_tariff.csv`. На судействе модель другая. Поэтому настраивать можно структуру
стратегии, но не константы под конкретные числа мока.

### Архитектура `agent.py`

```
build_prior()         change_tariff.csv -> средний эффект и доля переходов по связкам
Agent._candidates()   профиль + априор -> очередь гипотез для пилотов
Agent._explore()      пилоты push -> сжатые оценки с погрешностью
Agent._allocate()     оценки + лимиты -> канал для каждого сегмента
Agent._assemble()     сегменты -> до 10 кампаний, платные первыми
Agent._fallback()     страховка при исключении: безопасный минимум, не пустой список
```

Логика по шагам:

1. **Априор.** По истории смен тарифов считаем для связки (откуда, ARPU-сегмент, куда) среднее
   относительное изменение ARPU и долю переходов. История описывает другую выборку абонентов,
   поэтому априор используется только для ранжирования кандидатов и как точка сжатия.
2. **Кандидаты.** Ячейки аудитории (текущий тариф × `arpu_segment`) размером от 150 абонентов.
   Ранжирование по `эффект × средний ARPU × размер`. На 16 самых ценных ячеек — по одной лучшей
   гипотезе, оставшиеся пилоты уходят на вторую гипотезу для крупнейших ячеек.
3. **Разведка.** До 20 пилотов каналом `push`, по 200 абонентов. Стоимость — ноль.
4. **Сжатие.** `posterior = w * наблюдение + (1-w) * априор`, где
   `w = PRIOR_SD² / (PRIOR_SD² + 0.804²/n)`. При `PRIOR_SD = 0.10` и n=200 это w ≈ 0.76.
   В план идут связки с `posterior > Z_SAFETY * posterior_sd`.
5. **Распределение ресурсов.** Дефицитных ресурса два и они независимы: деньги и охват.
   Все положительные сегменты базово получают бесплатный `push`, затем бюджет тратится жадно —
   по убыванию прибавки эффекта на один рубль. **Канал у сегмента ровно один**, иначе одни и те
   же абоненты расходуют лимит охвата дважды (дедупликация всё равно оставит лучший).
6. **Сборка.** Сегменты с одинаковыми (ARPU-сегмент, цель, канал) объединяются в одну кампанию
   через `filter_current_tariff` со списком через `;` — слотов всего 10. Платные кампании
   ставятся первыми, потому что скоринг расходует бюджет и охват по порядку.

### Параметры (константы наверху `agent.py`)

| Параметр | Значение | Смысл |
|---|---|---|
| `PRIOR_SD` | 0.10 | априорный разброс эффекта; управляет силой сжатия |
| `PILOT_SIZE` | 200 | максимум на пилот, шум 0.057 |
| `MIN_CELL` | 150 | мельче не пилотируем |
| `Z_SAFETY` | 0.0 | запас прочности сверх сжатой оценки |
| `TARGETS_PER_CELL` | 2 | сколько целей проверяем на ячейку |
| `FIRST_PASS_CELLS` | 16 | ячеек в первом проходе |

## 5. Как запускать

Системный Python 3.13.3 без pandas. Окружение создано отдельно:

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск (данные должны лежать в корне: `customer_profile.csv` и `data/`):

```bash
python local_eval.py             # один прогон с полным отчётом
python local_eval.py --runs 10   # устойчивость по сидам
python make_submission.py        # submission.csv
```

**Грабли с кодировкой.** Консоль Windows здесь в cp1252, и вывод с кириллицей падает с
`UnicodeEncodeError`. Запускать так:

```bash
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 python local_eval.py
```

**Прогон произвольной конфигурации** без правки файла — параметры читаются как атрибуты модуля:

```python
import agent
from local_eval import evaluate_agent
agent.Z_SAFETY = 0.5
evaluate_agent(agent.Agent(), seed=7, verbose=False)["net_arpu_gain"]
```

## 6. Что не сделано

Идеи по убыванию ожидаемой отдачи:

1. **Оценка на уровне абонента, а не сегмента.** Сейчас `data_segment` и `call_segment` вообще
   не используются. Эффект внутри ячейки одинаков, но `predicted_arpu` разный — значит платный
   канал выгоднее направлять на подвыборку с высоким ARPU. Осторожно: если накрыть ячейку
   платной кампанией по подвыборке и бесплатной по всей ячейке, пересечение съест лимит охвата
   дважды. Выразить «ячейка минус подвыборка» фильтрами можно только перечислением остальных
   значений сегмента, а слотов всего 10.
2. **Повторные пилоты.** Все 20 расходуются одним проходом. Логичнее оставить 3–5 в резерве и
   до-пилотировать связки, у которых оценка близка к нулю — там решение и решает исход.
3. **Адаптивный размер пилота.** Сейчас всегда 200. Для заведомо крупных и дорогих ячеек это
   правильно, для мелких можно 100 и сэкономить охват.
4. **Использование бюджета.** Потрачено 35 %. Упирается в охват, а не в деньги, но точечный
   `call` по самым дорогим абонентам может окупиться (см. пункт 1).
5. **LLM в контуре.** Организаторы это приветствуют, но есть прямой конфликт с
   воспроизводимостью `submission.csv`. Безопасный вариант: LLM генерирует текстовое пояснение
   к готовому плану, не влияя на сам план. Ключ — только из `os.environ`.

## 7. Риски и на что смотреть

- **Мок не предсказывает балл.** Абсолютные числа выше — характеристика поведения, а не
  будущего результата. Переносится структура: бесплатная разведка, сжатие, экономика каналов.
- **Априор может не сработать.** Он построен по истории другой выборки. Если на судействе
  ранжирование связок окажется принципиально иным, пилоты уйдут не туда. Подстраховка —
  механизм второй гипотезы для крупных ячеек (`TARGETS_PER_CELL = 2`).
- **Клиппинг конверсии.** Пересчёт эффекта между каналами линеен только пока
  `conversion * множитель <= 1`. В коде клиппинг учтён, но при высокой конверсии выгода от
  дорогих каналов схлопывается — это нормально, а не баг.
- **Агент не должен падать.** `act()` обёрнут в try/except с фоллбэком: проведённые пилоты уже
  в зачёте, и пустой план оставит их без компенсации.
- **Детерминированность.** Любая своя случайность сломает сверку `submission.csv`.
